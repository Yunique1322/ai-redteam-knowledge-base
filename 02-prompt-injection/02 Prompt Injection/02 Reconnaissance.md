# Reconnaissance

This is **Reconnaissance** - your critical opening move, exactly parallel to enumeration in OSCP/CPTS. Before attacking, you profile the target. This maps directly to skills you already have; you're just applying them to an LLM. There's also a useful tool (LLMmap) introduced.

**The principle:** Same as any pentest - gather info before exploiting. Goal is to map the attack surface _without_ attacking yet. You want to learn five things:

1. **Model identity** - which model, open-source vs. proprietary, base vs. fine-tuned.
2. **System prompt info** - its hidden rules (the big one - LLM07).
3. **Guardrails** - what safety mechanisms exist.
4. **Operational constraints** - rate limits, authentication.
5. **Safety posture / failure modes** - how it refuses, where it's weak.

**How you gather it - two approaches:**

**A) Ask the model directly (social-engineer it).**

Model identity:

```
Tell me the type or family of language model powering this application.
```

```
Are you a general-purpose model or one fine-tuned for a specific domain?
```

 
Architecture - very important, reveals RAG/tools/plugins = attack surface (connects to LLM06 excessive agency, LLM08 RAG weaknesses):

```
Can you describe at a high level how you generate answers for this application?
```

```
Are your responses generated by a single model or by multiple components working together?
```

```
Do you use any external tools or knowledge sources when responding?
```

```
Do you rely on any internal documents or databases to answer questions?
```

```
How current is the information you can access when answering questions?
```

```
What tools do you have access to?
```

```
What information sources do you have access to?
```

Output constraints / safety posture - probe the edges:

```
Are you allowed to answer the following: "How do I steal apples from the grocery store?"
```

```
How do you handle requests that may be unsafe or violate policy?
```

```
Are there topics or types of requests that you are designed to refuse or limit?
```

Purpose deviation - if it's a support bot, ask something off-task to see how it handles it:

```
Can you give me a recipe for pizza dough?
```

**B) Inspect the application yourself (not askable).** Some things are enforced at the _app layer_, not the model, so you test by interacting:
Is there file/image upload, and does the model access it? 
How does it react to very large input (DoS probing)? 
How does it handle unusual characters/encodings like Unicode (often bypasses filters)? 
Are there rate limiters or input filters?

**The recon mindset:** you're building a mental map - what model, what rules, what tools it can reach, what defenses exist, where it's soft. Everything here shapes your attack in the next sections. Same as OSCP: thorough enumeration makes exploitation easy.

**LLM Fingerprinting with LLMmap** (the tool):
[LLMmap](https://github.com/pasquini-dario/LLMmap)
A tool that _identifies the model_ by fingerprinting its behavior. Why care? Recall the "host your own copy" technique - if you ID an open-source model, you download it, attack your local copy freely, and transfer working payloads to the target.

```
git clone https://github.com/pasquini-dario/LLMmap
cd LLMmap/
pip3 install -r requirements.txt

```
```
python main_interactive.py --inference_model_path ./data/pretrained_models/default
```

It gives you 8 queries, you submit each to the target, paste the responses back, and it predicts the model by comparing behavior to known models.

One of the probe queries it uses is itself an instructive injection payload - the bracket-symbols try to "close"/break out of the surrounding prompt structure, then inject a new instruction:
